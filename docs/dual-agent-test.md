# 단추 의뢰자·기관 에이전트 테스트

## 범위

2026-11-15 결정: 의뢰자용과 기관용 에이전트를 함께 제공한다. 첫 검증 대상은 요청서 작성 → 확인 후 전달 → 기관 참여 동의 → 추가 질문·답변 → 기관별 견적 초안 → 담당자 승인 후 제출 → 공개된 견적 비교이다.

현재 브랜치는 이 흐름을 **합성 데이터로 시험하는 로컬·초대 전용 미리보기 구현**이다. 실제 고객이나 기관으로 발송하지 않으며 운영 Supabase 데이터, 인증, 청구, 기존 요청 처리 코드를 수정하지 않는다. 운영 출시 또는 실제 기관 서비스와의 연결을 완료한 버전이 아니다. 미리보기 배포는 Vercel 팀 권한 승인과 환경 연결을 마친 뒤 검증해야 한다.

## 실행

프로젝트의 Git 제외 파일 `.env.local`에 설정된 `OPENAI_API_KEY`를 사용한다. 키 원문을 코드, 문서, 커밋, 로그에 넣지 않는다.

```bash
npm ci
DANCHU_AGENT_LAB=1 npm run dev -- --hostname 127.0.0.1 --port 3000
```

브라우저에서 `http://127.0.0.1:3000/agent-lab`을 연다. 로컬에서는 `NODE_ENV=development`와 `DANCHU_AGENT_LAB=1`이 모두 필요하다. 로컬 개발 서버는 루프백에 바인딩한다. Vercel 미리보기는 아래 조건을 모두 갖춰야 열리며, 운영 배포에서는 화면·API가 404를 반환한다.

### 초대 전용 미리보기 설정

대상은 `ddongsus-projects` 팀의 `danchu` 프로젝트, `feat/dual-ai-agents` 브랜치에 한정한다. 아래 값은 **해당 브랜치의 Preview 환경에만** 설정한다. 운영 환경과 다른 미리보기 브랜치에 공통으로 설정하지 않는다.

| 환경변수 | 설정 |
| --- | --- |
| `DANCHU_AGENT_LAB` | `1` |
| `DANCHU_AGENT_BLOB_STORE_ID` | 이 테스트를 위한 별도 private Blob 저장소 ID |
| `DANCHU_AGENT_ACCESS_HASH` | 무작위 32바이트 초대 코드(base64url)의 SHA-256 해시 |
| `DANCHU_AGENT_ACCESS_EXPIRES_AT` | 초대 링크의 만료 시각(ISO 8601) |
| `OPENAI_API_KEY` | 사용자가 승인한 단추 테스트 키. 서버 전용 Secret으로 저장 |

`VERCEL_ENV=preview` 및 `VERCEL_GIT_COMMIT_REF=feat/dual-ai-agents`는 Vercel 시스템 값으로 검사한다. 저장소는 별도로 만든 private Blob을 사용하며 `storeId`와 Vercel OIDC 인증으로 연결한다. 다른 파일 저장소를 공용으로 사용하지 않는다. 기존 Vercel Deployment Protection을 유지한다.

초대 링크는 `/agent-lab#access=<초대 코드>` 형식이다. 프래그먼트는 서버 접근 로그에 전송되지 않으며 화면이 읽은 즉시 제거한다. 코드는 POST로 검증하고 HttpOnly·Secure·SameSite 쿠키를 발급한다. 초대가 없거나 만료되면 테스트 API는 거절되며 AI를 호출하지 않는다. 초대 코드 원문과 키는 소스·PR·로그에 넣지 않는다.

이 미리보기는 하나의 테스터가 역할을 바꾸며 보는 합성 데이터 공간이다. 실제 기관별 운영 계정 인증을 대신하지 않는다. 최초 배포 후 초대 실패·성공, 화면 1440px/390px, 새로고침, 승인 재개와 실제 모델 흐름을 별도 확인해야 한다.

모델 기본값은 `gpt-5.6-terra`이며 `DANCHU_AGENT_MODEL`로 바꿀 수 있다. OpenAI Agents SDK가 애플리케이션 안에서 역할별 도구 실행을 담당한다. 서버에서 만든 도구 집합과 데이터 투영이 접근 범위를 결정하며, 모델이 보내는 역할이나 조직 ID를 신뢰하지 않는다. **이 테스트의 역할 전환 UI는 인증 시스템이 아니다.** 운영 서비스에서는 검증된 세션 사용자와 기관 ID로 역할을 고정해야 한다.

## 테스트 순서

1. 의뢰자에서 **예시 요청으로 시작**을 누르고 메시지를 보낸다. 요청서가 초안으로만 저장되는지 확인한다.
2. **기관에 요청 전달**을 요청하고 문서를 확인한 뒤 실행한다. 승인 전 기관에는 요청이 나타나지 않아야 한다.
3. 예시 기관 A에서 요약만 열리는지 확인한다. 참여 동의를 승인한 뒤 요청서 전체가 나타나야 한다.
4. 필요하면 추가 질문을 보내고, 의뢰자로 전환해 답변을 전달한다. 기관 B에는 기관 A의 질문이 보이지 않아야 한다.
5. 기관 A의 견적 초안을 작성하고 확인 후 제출한다. 같은 작업을 기관 B에서도 진행한다.
6. 두 기관이 모두 제출한 뒤 의뢰자에서 비교표가 열리는지 확인한다. ALT·AST·BUN·CREA 각각 30개 기준 예시 공급가 합계는 A 660,000원, B 600,000원이다. A에는 국문 결과 요약이 포함되고 B에는 별도이다. 실제 시장 가격이나 수행 조건이 아니다.
7. 기관 A 내부 메모가 의뢰자와 기관 B에서 보이지 않는지 확인한다.

## 제어와 제한

- 요청 전달, 참여 동의, 질문·답변 전송, 견적 제출은 SDK의 `needsApproval`로 중단한다. 확인 화면은 서버가 보관한 승인 ID에 연결되며 한 번만 사용할 수 있다.
- 승인 대기 중에는 다른 변경 대화를 진행하지 않는다. 서버에서 세션별 동시 실행도 차단한다.
- 참여 전 물질·메모를 가리고, 의뢰자의 비교표는 두 예시 기관이 참여하고 제출한 뒤 열린다. 기관은 다른 기관의 견적·내부 메모·대화를 볼 수 없다.
- 단가는 기관별 예시 카탈로그에서 가져오고 합계는 코드에서 계산한다. 미등록 항목의 금액은 `null`이며 제출이 차단된다.
- API 키는 서버에서만 사용한다. SDK 추적은 끄고 모델 요청에는 `store: false`를 사용한다. 공급자의 API 데이터 처리 조건을 변경하거나 보관 없음(Zero Data Retention)을 보장하는 설정은 아니다.
- 로컬 기록은 서버 메모리에 유지한다. 미리보기에서는 대화·역할별 기록과 SDK 승인 대기를 private Blob에 저장하고, 다른 서버 인스턴스에서 복원한다. 스냅샷은 브라우저로 보내지 않으며 추적 API 키를 직렬화하지 않는다.
- 세션 유효기간은 2시간이다. 만료 세션 조회 시 삭제하고, 새 세션 생성 후 오래된 기록을 정리한다. Blob에는 추가로 1일 자동 삭제 설정을 둔다. 데이터 초기화는 기존 기록을 덮어쓰지만 사용 횟수는 초기화하지 않는다.
- 미리보기는 ETag 조건부 갱신으로 같은 세션의 동시 변경·중복 승인을 차단한다. 중단된 서버의 잠금이나 호환되지 않는 SDK 승인 기록은 재실행하지 않고 세션을 종료한다.
- 세션별 AI 실행 최대 40회(마지막 1회는 승인 처리에 예약), 실행당 모델 턴 6회와 60초 제한이 있다. 미리보기의 시간당 30개 세션·120회 실행 한도는 저장소에서 모든 서버가 공유한다. 로컬에서는 메모리 세션 최대 30개와 프로세스별 시간당 실행 120회 제한을 쓴다.
- 실제 파일 파싱, 기관 단가표 업로드, 운영 계정 연동, 영구 저장, 예약·후속 연락, 실제 요청서 및 견적 API 반영은 후속 통합 범위다.

### 2026-11-15 최초 로컬 버전 검증 기록

- 타입 검사 통과. 린트 오류 0개이며 전체 저장소의 기존 경고 91개가 남아 있다. 새 에이전트 파일의 린트 경고는 없다.
- 전체 63개 테스트 파일, 755개 테스트 통과. 기존 첨부 권한 테스트의 가짜 저장소 URL 호출을 응답 fixture로 바꿔 네트워크 의존과 시간 초과를 제거했다. 중지 기관의 403과 승인 기관의 200을 모두 확인한다.
- 실제 OpenAI 호출로 초안 비공개, 전송 승인 거절·재승인, 기관 A·B 참여 승인, 기관별 견적 계산·제출 승인, 최종 비교 공개를 통과했다. 예시 합계 660,000원/600,000원을 확인했다.
- `ALT 분석`처럼 모델이 붙인 명확한 분석 접미어는 예시 코드로 정규화한다. 유사하거나 미등록인 검사명을 임의로 같은 검사로 간주하지 않는 회귀 검사를 추가했다.
- 프로덕션 빌드 통과. 개발 API의 다른 출처에서 온 쓰기 요청은 403으로 차단됨을 확인했다.
- **시각 검증 미완료:** 1440px/390px Playwright 검사를 시도했으나 실행 환경의 Chromium 소켓 제한으로 브라우저가 시작되지 않았다. 스크린샷, 실제 터치 조작, 화면 대비·배치를 검증했다고 간주하면 안 된다. 개발자 브라우저에서 위 순서와 밝은/어두운 화면을 확인해야 한다.

### 미리보기 대응 변경

초대·배포 환경 차단, private Blob 어댑터의 동시 갱신·공유 사용량 제한, 중단된 서버 처리, 실제 Agents SDK 승인 상태의 JSON 저장·복원 후 승인/거절을 자동 검사한다. 저장소 검사는 어댑터 fixture를 사용하므로 실제 Vercel Blob 연결 검증과 구분한다. 접근 권한이 없는 상태에서 배포 성공이나 화면 검증 완료를 주장하지 않는다.

변경 후 전체 64개 파일의 769개 테스트, 타입 검사, 프로덕션 빌드가 통과했다. 변경 파일의 린트 오류·경고는 0개다. 실제 배포 연결과 모바일 시각 검증은 Vercel 팀 접근 승인 이후에 수행한다.

## 운영 통합 전 확인

현행 PRODUCT.md와 실제 로직을 기준으로 참여 조건, 비교표 공개, 익명화, CDA, 사전예약 제한을 유지해야 한다. 운영 연동 시 기존 인증을 재사용하고, 승인 당시 문서 버전과 사용자·기관·유효기간을 DB에 기록하며 중복 실행을 DB 트랜잭션으로 차단해야 한다. 의뢰자·기관 간 직접 질의응답은 현재 운영 기능에 없으므로 별도 데이터 모델·접근 권한·알림 정책이 필요하다.
