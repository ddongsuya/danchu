# 제품 UX 전체 개선

기준: main `c486a82` · 브랜치: `improve/product-ux`

검토에서 나온 문구·입력·기능 불일치를 수정했다. 기존 그린 계열 시각 체계를 유지하며 요청 작성과 기관 회신, 견적 비교의 실제 작업 완료를 개선했다.

| Before | After | Why |
|---|---|---|
| 12개 순차 문항, 요약 수정 후 문항 재통과 | 4개 업무 단계, 직접 이동, 상세 조건 펼치기, 수정 후 요약 복귀 | 반복 입력과 우회 감소 |
| 같은 브라우저의 공통 초안, 저장 여부와 무관한 완료 표시 | 계정별 v2 초안, 저장 실패 표시, 이어쓰기·새로 작성 | 작업 보존 범위와 상태를 정확히 알림 |
| 첨부 실패 시 이메일 전달 | 접수 번호 유지, 파일만 재시도, 상세 화면에서 재첨부 | 중복 접수 없이 복구 |
| 자체 CDA가 보호 조건에서 누락 | 공통 접근 정책과 기관별 CDA 확인·회수 UI/API | 회사명·첨부 공개 경계 일치 |
| 요청 수와 무관한 전체 배포 | 앱의 잔여 수 확인과 DB 트리거의 최종 제한 | 자동·수동·보충 배포 모두 상한 적용 |
| 기기 안에서만 바뀌는 이메일·푸시 토글 | 계정에 저장하는 이메일 설정, 발송 시 반영, 미구현 푸시 제거 | 실제 동작하는 설정 제공 |
| 가격 최저가·순위 강조 | 수행 범위·제외 비용 우선, 중립 정렬, 하나의 비교표 | 다른 시험 범위의 단순 가격 순위 방지 |
| 예비·만료 견적도 선택 가능 | UI/API/DB에서 정식 PDF·착수일·유효기간 확인 | 확인되지 않은 조건으로 기관 선정 방지 |
| 입력 수정만으로 기관 확인 경고 해제 | 명시적 확인, 초안에 확인 상태 보존, 저장 재시도 | 검토할 조건 유실 방지 |
| 가입/로그인 기본 경로 불일치 | 이메일 링크 기본, 추가 프로필 접기, 확인 메일 재전송 | 가입 후 재방문 과정 일관성 |
| 입력 이름·파일 키보드 접근 부족 | 명시적인 입력 이름, 파일 입력 노출, IME Enter 보호 | 한국어·키보드 입력 지원 |
| 재방문할 때 달라지는 완료 일정 | 저장된 회신 기한과 실제 전달 현황 표시 | 화면과 실제 요청 상태 일치 |

## 배포 전 필수 작업

1. 대상 Supabase 프로젝트를 확인하고 `supabase/migrations/0008_product_ux.sql`을 먼저 적용한다. 이 세션에서 운영 DB에는 접속하거나 적용하지 않았다.
2. 마이그레이션은 `rfq_invites.cda_signed_at`, `cda_reference`, `profiles.email_notifications`와 초대 수·견적 선정 트리거를 추가한다. 기존 데이터는 삭제하지 않는다. 기존 CDA 체결은 자동으로 추정하지 않으며 운영자가 확인 근거와 함께 기관별로 등록한다.
3. 기관별 체결 상태를 확인한 뒤 앱을 배포한다. CDA 공개 범위는 회사명과 첨부이며, 시험 개요는 먼저 전달된다는 안내를 요청서·FAQ·안내·약관/개인정보 문구에 맞췄다. 공개 정책과 운영 방식이 같은지 담당자가 확인한다.
4. 운영 인증 계정으로 미체결/체결 상태의 CRO 포털·토큰 링크·첨부 다운로드, 이메일 설정, 요청 접수·기관 회신을 확인한다. 실제 메일·Storage 업로드는 이번 로컬 검사에서 호출하지 않았다.

브랜치가 배포될 때 `DANCHU_DESIGN_PREVIEW`는 기본값(미설정)을 유지한다. 검토용 합성 데이터 페이지는 `DANCHU_DESIGN_PREVIEW=1`인 로컬에서만 활성화했다.

## 검증

### 로그인 없는 요청서 체험

Vercel Preview 배포의 `/request-preview`에서 실제 요청서 컴포넌트로 단계 이동, 입력, 요약 수정을 확인할 수 있다. 예시 담당자와 별도 브라우저 초안을 사용하며 제출·파일 업로드는 차단된다. 운영 배포(`VERCEL_ENV=production`)에서는 404를 반환한다. 로컬에서는 `DANCHU_DESIGN_PREVIEW=1`로 활성화한다. 기존 인증 경로나 접근 권한은 변경하지 않는다.

- `npm run typecheck` 통과
- `npm run test`: 50개 테스트 통과. 양쪽 CDA 유형의 파일 접근, 만료 토큰, 의뢰자 소유 권한, 계정별 초안, 저장 실패, 배포 수, 예비/만료 견적 선정 정책 포함
- `npm run build` 통과
- PostgreSQL 호환 PGlite에서 마이그레이션 적용 및 트리거 9개 검사 통과. 최소 스키마 기준이며 운영 Supabase/RLS와 동시 다중 연결 부하 검증을 대체하지 않는다.
- Playwright 1440px/390px: 실제 요청서/회신/비교 컴포넌트를 옵트인 미리보기에서 확인. 새로고침 후 초안·단계·기밀 선택 복원, 첨부 재선택, 요약 수정 복귀, 저장 실패 재시도, 확인 경고 유지, 참여하지 않기 링크 확인. API 쓰기는 모두 로컬 테스트 응답으로 차단/대체했다.
- 1차 확인에서 모바일 회신의 가로 넘침을 발견해 grid 최소 폭과 확인 버튼 줄바꿈을 수정했다. 최종 결과는 `browser-check.json`, 화면 PNG에 보관한다.

## 의도적으로 남긴 범위

- 초안은 서버 동기화가 아닌 계정별 브라우저 저장이다. 파일 바이트는 저장하지 않고 재선택할 이름/크기를 유지한다. 시험 찾기 답변은 요청서 적용 전에는 임시 저장되지 않으며 화면에서 안내한다.
- NDA/CDA 전자서명 자체를 구현한 것은 아니다. 외부 체결 후 운영자가 근거를 기록하고 공개 범위를 변경한다. 비공개로 되돌려도 이미 받은 파일은 회수되지 않으며 발급된 다운로드 URL은 만료까지 최대 5분 유효하다.
- 이미 상한보다 많이 전달된 과거 요청은 소급 취소하지 않는다. 앞으로의 초대 추가를 제한한다.
- 기존 소유자 없는 v1 초안은 다른 계정으로 잘못 이어지지 않도록 폐기한다.
- 새 디자인을 다시 만드는 작업, 자동 규제 적합성 판정, 견적 PDF 자동 추출, 실시간 채팅은 이번 범위에 추가하지 않았다.
