# 비임상 가이드라인 질의응답

단추 저장소에는 공개 가이드라인(ICH, 식약처 고시, OECD TG, 화장품·의료기기·화학물질 규정)을 "이 상황이면 이 시험이 필요하다"는 규칙으로 압축해 둔 코드가 있다. 이 스킬은 그 규칙을 사람이 읽는 참고 문서로 뽑아 둔 것이다. 질문에 답할 때 기억에 의존하지 말고 참고 문서에서 찾아 **근거 조항을 붙여** 답한다. 근거가 참고 문서에 없으면 그렇게 말한다.

## 답하는 순서

1. **질문의 유형을 정한다.** 아래 표에서 맞는 참고 파일을 고른다. 한 질문에 둘 이상 해당하면 둘 다 읽는다.
2. **참고 파일에서 해당 행을 찾는다.** Grep으로 항목명(예: "반복투여 13주", "hERG", "소핵")이나 규칙 번호(예: "R-A4")를 찾는 것이 빠르다. `04-제안규칙-전체.md`는 제품 유형별 섹션으로 나뉘어 있으니 해당 유형 섹션부터 본다.
3. **답을 쓴다.** 결론 한 줄, 근거 조항, 조건이 갈리는 지점(임상 기간·제출처·적응증·보유 자료), 기관마다 다른 부분 순서로 쓴다.
4. **면책을 한 줄 붙인다.** "공개 가이드라인에 근거한 참고용이며 최종 설계는 시험기관·규제기관 상담으로 확정한다." 이 문장은 단추의 중립 원칙이자 법적 안전장치라 빼지 않는다.

규칙 번호(R-A1-01 등)는 저장소 밖 `기술문서/` 폴더의 규칙 번호와 같다. 그 폴더가 `references/source/`에 있으면 원문을 우선한다. 없으면 참고 파일의 압축 규칙으로 답하고 "원문 확인 필요"를 붙인다.

## 지켜야 할 것

- **기관마다 다른 부분은 값을 정해 주지 않는다.** 회복군 마릿수와 지정 방식, 분석법 검증 횟수, 조직병리 범위 같은 것은 참고 문서에 "기관마다 다름"으로 적혀 있다. 그대로 답한다. 단추는 중립 플랫폼이라 기준을 정하는 쪽으로 보이면 안 된다.
- **숫자는 최소값이다.** "설치류 군당 암수 각 10마리 이상"은 고시의 최소치다. "20마리여야 한다" 같은 응용 기준은 참고 문서에 없으므로 만들어 내지 않는다.
- **조건이 갈리면 갈린다고 말한다.** 같은 질문도 임상 기간, 제출처(식약처·FDA·EMA), 적응증(진행암), 가임 여성 포함 여부, 보유 자료에 따라 답이 다르다. 사용자가 조건을 안 줬으면 가장 흔한 경우로 답하고 어떤 조건에서 달라지는지 덧붙인다.
- **화면 문구 규칙.** 답에 `—`, `–` 대시를 쓰지 않는다. 하이픈이나 마침표를 쓴다.

## 예시

**질문**: "임상 3개월 투여 예정인데 반복투여 몇 주 해야 돼?"

**답 뼈대**: 임상시험 진입용이면 설치류·비설치류 모두 13주(ICH M3(R2) 표 1). 품목허가 신청용이면 6개월(표 2). 진행암이면 기간이 아니라 임상 일정으로 정한다(ICH S9 §3.3). 13주 전에 더 짧은 반복투여 자료가 먼저 필요하다(고시 별표 2 ② 2). 참고용 안내이며 최종 설계는 기관·규제기관 상담으로 확정.

**질문**: "항체 의약품도 Ames 해야 하나?"

**답 뼈대**: 통상 불필요. DNA와 직접 반응하지 않는 단백질 의약품에는 표준 유전독성 배터리가 적용되지 않는다(ICH S6(R1)). 링커·저분자 부분이 있는 ADC는 예외. `04-제안규칙-전체.md`의 바이오의약품 섹션에서 해당 행을 찾아 근거를 붙인다.

## 참고 문서 갱신

원천은 `lib/advisor.ts`, `lib/design-guide.ts`, `lib/presets.ts`, `lib/efficacy.ts`, `lib/faq.ts`다. 코드가 바뀌면 아래를 실행해 참고 파일을 다시 만든다. 참고 파일을 손으로 고치지 않는다.

```bash
node --experimental-strip-types --no-warnings --import ./scripts/ts-register.mjs scripts/build-guideline-skill.mjs
```
